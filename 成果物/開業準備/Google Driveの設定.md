# Google Drive の設定（2026-09-25）

完成した動画を Drive に自動で入れる仕組みの設定。**あなたの手が必要なのは3つだけ**で、
残りはコード側で済んでいる。

---

## なぜ触るのか

Drive の認証が**7日で切れて**いた（8/28に取ったものが9/22には失効）。
原因は Google の同意画面が「**テスト中**」のままだったこと。テスト中のあいだ、
Google は更新用トークンの寿命を7日に制限する。

本番公開すれば消える。ただし**要求している権限によって公開の難易度が変わる**。

| スコープ | 分類 | 本番公開の条件 |
|---|---|---|
| `auth/drive`（全ファイル） | **制限付き** | 審査＋年1回のセキュリティ評価（CASA）。個人事業では無理 |
| `auth/drive.file`（このアプリが作ったファイルだけ） | **機微でない** | **条件なし。すぐ公開できる** |

9/22 に「手で作ったフォルダに書けない」という理由で `drive` へ広げていたが、
**置き場をアプリ自身に作らせれば `drive.file` で足りる**。そう直した。

---

## あなたがやること（3つ）

### ① 同意画面のスコープを入れ替える

1. **https://console.cloud.google.com/auth/scopes** を開く
2. プロジェクトを選ぶ（分からなければ **https://console.cloud.google.com/auth/clients** を
   各プロジェクトで開いて、`.env` の `GOOGLE_DRIVE_CLIENT_ID` と一致するものがある方）
3. `.../auth/drive` を**外す**
4. `.../auth/drive.file` を**足す**

### ② アプリ名を直して、本番公開する

1. **https://console.cloud.google.com/auth/branding** で、アプリ名が
   `somethingfun` 等になっていたら **`so-creative`** に直す
   （前職の社名のままだと、ブランド審査で「その名前を保有している証明」を求められる）
2. **https://console.cloud.google.com/auth/audience** を開く
3. 「公開ステータス: **テスト中**」の下の「**アプリを公開**」を押す

`drive.file` だけなら審査は要らないので、ここで完了する。

### ③ つなぎ直す（必須）

**いまのトークンは `drive` 用なので、そのままでは使えない。**Mac で1回：

```bash
cd ~/so-portfolio/discord-groupchat && venv/bin/python tools/drive_auth.py
```

ブラウザが開くので「許可」を押すだけ。コードの貼り付けは要らない。

⚠️ **これをやるまで、完成した動画は Drive に入らない。**

これは仕様として作り込んである。いまのトークンには「`drive` を許可した」と
記録されていて、要求する `drive.file` を満たしていない。ボットは**読む前に
その記録を突き合わせて、足りなければ「繋がっていない」ものとして扱う**。

なぜそうしたか：google-auth は要求スコープを明示して読み込むと**ファイル側の
記録を捨てる**。そのため古いトークンがそのまま通り、更新に成功したあと
「`drive.file` を許可済み」という**嘘の記録で上書き**されてしまう
（2026-09-25 に実測して確認）。こうなると狭めた意味が無いうえ、繋ぎ直しが
必要だと誰も気づけない。だから黙って使わない。

黙って失敗するのではなく、**毎朝9時に Discord で「認証が切れています」と言う**。

## 変わったこと

| | 前 | いま |
|---|---|---|
| スコープ | `auth/drive`（全ファイル） | **`auth/drive.file`**（アプリが作ったものだけ） |
| 置き場 | 手で作ったフォルダ（`1Tso…`） | **アプリが作る「so-creative」**（マイドライブ直下） |
| 鍵の名前 | `somethingfun_CLIENT_ID` | **`GOOGLE_DRIVE_CLIENT_ID`**（旧名も読むので入れ直し不要） |
| トークンの寿命 | 7日 | 公開後は**切れない** |

置き場の中の仕切り（`動画` / `画像` → 案件ごと）は前と同じ。
`成果物/<案件>/` と同じ名前で仕切るので、GitHub と Drive を行き来しても迷わない。

### 手で置いたファイルは見えなくなる

`drive.file` の代償はこれ。**ボットは自分が上げたものしか探せない。**

- 「**ドライブ一覧**」…ボットが上げたものだけ出る
  （アプリが作ったフォルダとゴミ箱は除いてある。そうしないと
  `so-creative` や `動画` が「上げたファイル」として並んでしまう）
- 「**ドライブから取って ○○**」…ボットが上げたものからしか探せない。
  見つからない時は、その理由まで返す

お客様から素材をもらう側は、**Claude Code のセッション（Drive コネクタ）が担当**する。
そちらはアカウント側で認証するので、7日問題も無く、Drive 全体が見える。

### 旧フォルダ（`1Tso…`）

中身はそのまま残る。必要なら手で移す。移さなくても上げる側は困らない。
`DRIVE_UPLOAD_FOLDER` にこのIDを指定しても**無視される**（`drive.file` では書けず、
黙って404になり続けるため）。
