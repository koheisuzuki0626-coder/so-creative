# 初稿を出す前の社内チェック

提出前に自分で潰しておく項目。実案件でそのまま使う。

## 出す前に必ず直す

- [ ] **リンクの寿命**。いま貼っているのは CloudFront のURLで、期限が切れる。
      実案件では自社のGoogle Drive等、消えない場所に置いてから送ること。
      クライアントが1週間後に開いて「見られません」は事故になる
- [ ] **仮の数字を仮だと書く**。92%をそのまま黙って出さない。
      先方が社内会議でスクショを回して独り歩きするのが最悪のパターン
- [ ] **仮のロゴを仮だと書く**。勝手に作ったマークを本番扱いされない
- [ ] ファイル名に案件名と稿数を入れる（`想工業_会社紹介_60s_初稿.mp4`）

## 提出メールに必ず入れる

- [ ] 回答期限の日付（「お早めに」だけでは動かない）
- [ ] 「1通にまとめれば何項目でも修正1回」（分割送信を防ぐ。先方にも得な条件として出す）
- [ ] 残りの修正回数（3回のうち何回消化したか）
- [ ] 確認が遅れた分だけ納品がずれること（初稿提出時に改めて書く。契約時に言っただけでは忘れられる）
- [ ] 見てほしい観点の指定（「いかがでしょうか」だけだと感想しか返ってこない）

## AI制作ならではの項目

- [ ] 登場人物が実在しないことを明記
- [ ] 「※ 本映像はイメージです」の表記の可否を確認
- [ ] 名前・役職を付けていないことを伝える（応募者の誤認防止）
- [ ] 設備が実機と違う点があれば、該当カットだけ差し替えられると伝える
      （実写と違い全編撮り直しにならない、が最大の利点）

## 出した後

- [ ] 返信が来なければ期限当日に一度だけリマインド
- [ ] もらった修正指示は、着手前に「この内容で1回目として進めます」と復唱する
      （後から「あれは修正に入らない」と揉めるのを防ぐ）
