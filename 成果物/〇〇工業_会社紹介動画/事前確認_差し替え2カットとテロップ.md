## #5 は一度失敗している（重要）

**t2v の初回は、主軸とクーラントノズルが付いた画になった。**
マシニングセンタかレーザー加工機に見え、ワイヤーカットの特徴
（上下のガイドに張られた細いワイヤー、加工液に沈んだワーク）が一つも出なかった。

**モデルがワイヤーカットという機械を知らない。**
`no rotating spindle, no milling cutter, no laser beam, no coolant nozzles` と
否定形で潰し、ワイヤーを "stretched taut and perfectly vertical like a fine thread,
running from a ceramic guide head above down to a matching guide below" と
**形状で描写**して、ようやく通った。

### 手順を変えたのが効いた

**動画で試行錯誤しない。静止画で形を確定させてから動画化する。**

1. `nano_banana_pro` で静止画を2案（寄り／引き）生成
2. 正しい方を選ぶ（引きの方が制御パネルと真鍮スプールまで写り、
   3年落ちで大事にされている機械に見えた）
3. その job_id を `medias: [{role:"start_image", value:<job_id>}]` で渡して動画化

静止画は速く安く、間違いが一目で分かる。**動画で当てにいくと時間もクレジットも溶ける。**

**実案件なら、ここは先方からもらった写真を `image_references` で渡すのが正解。**
文章で機械を説明して当てにいくのは、参照がない時の次善策でしかない。

## イン点は測って決めた（結果は「動かす理由なし」）

火花の強さが時間で変わるかを `signalstats` で実測した。

```
ffmpeg -i n05b.mp4 -vf "crop=400:300:660:120,signalstats,\
  metadata=print:key=lavfi.signalstats.YMAX:file=sig.txt" -f null -
```

2秒窓の平均 YMAX は開始0.0秒で877、3.0秒で868。**差は約1%。**
イン点を動かす理由がないので、**頭の不安定を避けて1.5秒のまま**にした。

推測で「頭の方が火花が強そう」と動かさなくて済んだ。
