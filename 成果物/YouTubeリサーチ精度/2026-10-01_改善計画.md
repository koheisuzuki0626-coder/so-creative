## 2. 原因（重い順）

### 原因1｜視聴して別物と分かっても、型の材料から外れない（off 73本＝29%）

**何が起きているか**：Gemini は本文で正しく見抜いている（「解説者本人が正面から視聴者へ直接語りかける」「実写撮影のため」「全体的にPC画面のキャプチャ映像」）。その本文はレポートに残るが、**判定として読み戻す経路が1本も無い**。結果、ノウハウ解説動画から「採用動画の型」＋見積り約246,800円、画面キャプチャから「アニメーション説明動画の型」＋約398,700円が `fixtures/youtube_insights.md` に残った（実物を確認済み）。
さらに視聴プロンプトが先入れしている：`study_prompt = VIDEO_STUDY_PROMPT + f"\n特にリサーチ目的『{query}』の観点を最優先で分析して。"`（6839-6841）が、`VIDEO_STUDY_PROMPT`（5290）の「推測では書かず、実際に見えたものだけを書く」と矛盾する。

**どこ**：`_run_trend_study` の `study_prompt`（6839-6841）／`reports.append`（6874）／`digest_src`（6957）

**直し方**：
1. `VIDEO_STUDY_PROMPT` に判定を1問足す。**番号は ⓪ か ⑩**（⑧は「AIで再現できるか」が使用中。番号を振り直すと test_routing.py:1741 の①〜⑨通し検査が「字は残る」ので**通ったまま項目が消える**）。
2. 同じコミットで 6839 の前振りを書き換える（「お題は『{query}』。ただしこの動画がお題の実物でない場合は、お題に寄せず⓪で『違う』と書く」）。片方だけだと同じ1回の呼び出しの中で先入れと判定が矛盾する。
3. **`reports` には触らない。** 新しく `_kata_src = [(v,a) for v,a in reports if verdict[v["id"]] != "違う"]` を作り、`digest_src`（6957）だけを差し替える。`reports` を減らすと `require_video and not reports`（7025）で「動画の視聴に失敗した（枠切れではない）」＝嘘の理由を報告し、`_mark_analyzed`（6880）も走らず翌日また同じ off を視聴する。
4. 「違う」だけ外す。**「近い」は落とさない**（adjacent が全体の22%。落とすと材料が枯れる）。曖昧・無回答・解析失敗は全部「実物」に倒す（`_ai_route_veto` と同じ片側）。
5. `_note`（6818-6823）は**加算**（`・お題の実物でない N本`）。減算してはいけない（6812-6817 のコメントが「数えられる事実を書く／直したい事象だけがログから見えないのは一番まずい」と明記）。
6. `_kata_src` が空の回は `_no_hit` の既存文へ合流させる。**新しい `_trend_fail_why[cid]` を足さない**（test_routing.py:1924 が `count == 4` を固定）。

**①守り手**：AIへの1問（正規表現ではない）＋ コード側が材料を選ぶ。判定行は digest へ渡す前にコードで外す（プロンプトの案内文が返事に混ざる事故が過去3回）。
**②テスト**：判定文の解釈だけを `ai_group_chat.py` 内の関数に切り出し、「違う／ちがう／実物ではない／近い／無回答／解析失敗」の6ケース＋「全部違うでも視聴本数を0にしない」を1件。`simulate.py:280` が `_run_trend_study` を丸ごと差し替えているのでE2Eは効かない。**別ファイルへ出さないこと**（モジュール変数の差し替えが届かず空回りする）。

### 原因2｜当たり判定が題名・チャンネル名・説明文・タグを同点で数える（誤当たり44本）

**何が起きているか**：`_query_match_score`（4941-4957）は4フィールドを同じ重みで数える。制作会社の概要欄には9ジャンルの語が目次として並ぶので（NTPの3本は説明文が完全に同一で9ジャンル語を列挙）、題名に一言も無い動画が「当たり」になる。`_no_hit` が消えた回が **34回中9回**。
ただし**一律に説明文を外してはいけない**：同じ44本のうち本物のMV 8本と GJC のサービス紹介 exact 2本は説明文由来。4944-4947 のコメントがこの事故を記録している。

**どこ**：`_query_match_score`（4941-4957）／`_hits`（6797）／`_pool`（6798-6801）

**直し方**（この形以外にしない）：
- `_query_match_score` の**中で**出処に重みを付ける（題名・チャンネル名=3／説明文・タグ=1）。
- **`>0` の閾値（6797）・`_relevance_score` の式（4959-4966）・`score_fn=(lambda v: _relevance_score(v, query)) if query else None` の行（6810）を一字も変えない。** これで `_hits` の母集団・`_no_hit` の発火条件・`_pick_diverse` の strong/weak 境界の3つに一切触らずに、層内の並びだけが直る。
- 「どこで当たったか」を返す別関数（`_query_match_where` など）を足して `_note` に出す。**返り値をタプルにしてはいけない**（`_relevance_score` の `* 10` が壊れ、test_routing.py:1652 の `== 0` が落ちる）。

**①守り手**：状態（どのフィールドで一致したか）で判定。
**②テスト**：「題名当たりが説明文当たりより先に並ぶ」1件＋**対で**「説明文だけの当たりでも `_hits` に残る」1件（test_routing.py:1614「説明文に書いてある本物も拾う」を壊していないことの確認）。

### 原因3｜「当たり0本」の警告が全か無かで、しかも視聴した5本を見ていない

**何が起きているか**：`_no_hit = bool(query) and not _hits`（6806）は**候補プールに対して0本**の時だけ立つ。一方 `_pool` が候補全体に戻るのは `len(_hits) < min(TREND_DEEP_COUNT, 3)`（6798）。**この1〜2本の帯では「裾から5本埋めて、しかも型として一般化してよい」状態になる。** 数学的に「視聴分の当たり≤2」⟺「`len(_hits)<3`」なので、門は1つでよい。
さらに 6998 の `f"見た5本は「{query}」ではなく…"` はハードコードで、`insights/2026-09-30_MV_制作実績_2.md` は**視聴1本で⚠️発火**＝嘘の前提がAIに渡っていた（実物で確認）。

**どこ**：`_hits`/`_pool`/`_no_hit`（6797-6806）／`_note`（6818-6823）／`digest_prompt`（6996-7001）

**直し方**：
- `_no_hit` の式と「お題の語に当たった動画は0本」の文言は**触らない**（test_routing.py:1706／1711 が逐語検査）。`targets` 確定後に `_hit_seen = sum(1 for v in targets if _query_match_score(v, query) > 0)` を足し、こちらを表示・分岐に使う。`_no_hit` は「そのお題に公開事例がほぼ無い」の意味で残す（2つは意味が違うので統合しない）。
- `_note` は**末尾に足す**。表示は**しきい値未満の回だけ**（満たしている回に「5/5本」と書くと、精度54%の判定を「実物」と名乗る新しい嘘になる）。
- `tailfill` は `if _hits:` / `else:` の2分岐に組み替える。逐語 `_pool, _n = _hits, min(TREND_DEEP_COUNT, len(_hits))` をそのまま残せば test_routing.py:1934／1770 は無傷で、`min(5,1)=1` なので本数も自動で当たりに合う。**0本の回で `return False` にしてはいけない**（`_trend_fail_why` が嘘になり、`_mark_trend_fail` の倍々待ちで健全なジャンルまで止まる）。
- 6998 を `f"見た{len(reports)}本は"` に（`if reports:` の中なので必ず1本以上）。**この1行は依存ゼロで単独で入れられる。**
- digest_prompt に新しい条件ブロックを挟むときは `_no_hit` ブロックの**手前**に置く（test_routing.py:1709 が `if _no_hit else "")\n            + "【トレンド概観】` を**改行と字下げまで含めて**固定）。

**①守り手**：本数（状態）で分岐。
**②テスト**：「視聴した5本が全部外れなら数字が出る」1件＋**対で**「`_hits>=3` の回には新しい注記が付かない」1件。あわせてリポジトリ直下 CLAUDE.md の守り手の表（`_no_hit` の行）も同じコミットで直す。

### 原因4｜トレンド概観が未視聴100本＋再生数から書かれ、レポートの第1節として残る

**何が起きているか**：`listing`（6883-6886）は `enumerate(videos)` ＝**尺フィルタ・除外・`_corp_gate` の全部より前の生のAPI結果（最大100本）**に `{v['views']:,}回` を付けて渡す。`overview_prompt`（6896-6899）は「① 伸びているジャンル ② タイトル・**サムネ**の傾向」を聞くが、公開日（`_video_dict` 4729-4743 に `publishedAt` が無い）もサムネも渡していない。`e1f2f20` で「再生数の多寡を論じないこと」という一文を足したが、09-30 の概観16本は**16本すべて**が伸び系の語を使っている（文章で禁じても効かない実例）。概観の引用再生数が当日の視聴最大の3倍超だったレポートは 123本中37本、09-27以降の35本では21本。
`meta_prompt`（6916-6923）も同じ欠陥（未視聴 `videos[:20]` ＋再生数＋渡していないサムネ）で、こちらは digest が作れない回の digest 本体になる。

**訂正（優先度を上げる根拠にはしないこと）**：`discord-groupchat/.gitignore:7` に `insights/` が入っているので、レポート全文は**Macローカルにしか無く GitHub に出ない**。`fixtures/youtube_insights.md` への概観の逐語流出は 14件（全部 09-18 以前・`require_video=True` で 09-19 以降は塞がっている）、「今日の型」144件のうち再生数系は1件。買えるのは「本人がローカルで読む第1節が検証可能になる」「`digest_prompt`（7003）に未視聴100本の前提を渡すのをやめる」の2つ。

**どこ**：`listing`（6883-6886）／`overview_src`（6890-6895）／`overview_prompt`（6896-6899）／`meta_prompt`（6916-6923）／`full`（6935-6940）／`digest_prompt`（7003）

**直し方（同じ4行の塊を触る案が11件あるので必ず1コミットにまとめる）**：
1. お題ありの `listing` から `{v['views']:,}回` を落とす（急上昇＝`query is None` 側は順位に意味があるので残す）。`overview_src` の禁止文は消す（文章の縛りを残すと次に読む人が「文章で守れている」と誤解する）。
2. `listing` の母集団を `candidates` にする。**`_hits` にしてはいけない**（誤当たりをそのまま概観に持ち込み、かつ `_no_hit` 31%なので概観が空になる回が3割出る）。`_ov_pool = candidates if (query and len(candidates) >= 3) else videos` の**退避は必須**。退避の閾値は `_hits < 3` の門とは**別の変数**で持つ（後から連動して黙って変わる）。
3. `overview_prompt` の①を「この検索語で実際に多い企画・尺・業種（数えられる範囲で）」に、②から「サムネ」を削除。`meta_prompt` も同時に同じ直しをする（概観だけ直すのは「発言が通る道を最後まで追う」違反）。
4. 保存レポートの見出しを `## 検索結果一覧の傾向（未視聴・題名とチャンネル名のみ・N本）` にし、直前に `_drop_why` の内訳を1行足す（いまは Discord の通知にしか出ず、レポートに残っていない）。**`## ランキング全体の傾向分析` というコメント文字列（6882）は残す**（test_routing.py:4319-4321 が境界に使っており、消すと `ValueError` で `_load_analyzed_ids` 周りのテストごと死ぬ）。
5. 概観を控える形にするなら、6936 の `overview or "（取得失敗）"` と 7013 の `or "（本日は分析結果を取得できませんでした）"` も同時に直す（意図して控えた回に「取得失敗」と書くのは `_FAKE_STATE_RE` が禁じている側）。

**①守り手**：渡す材料を変える（言い方の禁止文に頼らない）。
**②テスト**：「お題ありの `listing` に `回` が無い／急上昇側には有る」「`listing` の材料が `videos` 直接でなく退避付きの候補」「`overview_prompt` に『サムネ』『伸びているジャンル』が無い」「`meta_prompt` に『サムネ』が無い」。7003 を落とす場合は test_routing.py:1709 の隣接リテラルを新しい隣（`+ "\n\n【個別分析】"` 等）に張り替え、**「概観をダイジェストに渡さない」を1件足す**（第2条件を消すだけの直し方をしないこと。あれは 09-30「研修動画15本が1本も研修動画でないのに型にした」事故の守り手で、警告が digest_prompt の中に**繋がっていること**を位置で保証している）。

### 原因5｜言い換え表が、現行9ジャンルのうち2つに届かない（構造の到達不能）

**何が起きているか**：`_term_variants`（4921-4925）は `_query_core`（4916）で末尾の一般語を落とした**核**をキーに `_QUERY_ALIAS` を引く。実際に9ジャンルを通して測った結果：

| お題 | 核 | 返る変種 |
|---|---|---|
| コーポレートムービー 制作事例 | コーポレート | **`['コーポレート']` のみ** |
| マニュアル動画 制作事例 | マニュアル | **`['マニュアル']` のみ**（`研修` の別名側に片方向で入っているだけ） |
| アニメーション 説明動画 制作事例 | アニメーション／**説明** | 説明（2文字）は別名0 |
| SNS広告 縦型 事例 | SNS広告／縦型 | 「縦型」が**二重計上** |

`_QUERY_ALIAS` のキー `ミュージックビデオ` は核が「ミュージック」なので**到達不能**（実行して確認）。09-30 に「会社紹介動画」→「コーポレートムービー」へ改名した瞬間に、言い換えが黙って消えた。

**どこ**：`_QUERY_ALIAS`（4899-4913）／`_query_core`（4916-4918）／`_term_variants`（4921-4925）

**直し方**：同義集合＋逆引き（**グループ単位。推移的な融合をさせない**——1語が2グループに入ると2ジャンルが1つに融合する）。核と生の語の両方で引く。「コーポレート」は**複合語だけ**（`コーポレートムービー|コーポレートビデオ|コーポレートPV|コーポレート動画`）、「会社概要」は題名限定（実データに社名「オンワードコーポレートデザイン」と説明文「弊社の会社概要」で off が4本立つ）。語の重複は1点に畳む。

**効果の言い方**：**稼働9ジャンルでの当たり本数の実測変化は ±0**（過去に測れた伸びは引退お題ミュージックビデオ由来）。買うのは精度ではなく「**次にジャンル名を変えたときに黙って壊れないこと**」。

**①守り手**：表の形ではなく**到達可能性**。
**②テスト（これが本体）**：①「`gen_settings.trend_query` の**全ジャンル文字列**について `_term_variants` が2語以上返る」②「`_QUERY_ALIAS` の全キーは `_query_core` を通しても自分自身」。現状 `_QUERY_ALIAS` を差し替えているテストは1件も無いので、表の形を変えても既存テストは何も気づかない。**この2件を同じコミットで入れることが表を触る条件。**

### 原因6｜制作会社の集客ノウハウ解説・セミナーが視聴対象に残る（527本で10本）

### 原因7｜カット数×平均秒数が実尺と合わないのに「数えた値」として保存される（202本中28本＝14%）

**何が起きているか**：「総計21カット（数えた値）／平均約1.5〜3秒」が実尺245秒の動画に付く。「12カット・数えた／平均2.5秒」が91秒に付く。実尺はコード側が持っているのに（`v["duration"]`）、Gemini にも digest にも渡していないので検算されない。>50%外れは17本（7%）。「数えた」は不整合率10%、「推定」25%、どちらも無し31%＝ラベル自体は信用度の目安として機能している。

**どこ**：`study_prompt`（6839）／`reports.append`（6874）／`full` の見出し（6940）／`digest_src`（6957）

**直し方**：
- 材料を渡す（追加クォータ0）：`study_prompt` に「この動画の長さは{duration}秒」、6940 の見出しに `／{duration}秒`、`digest_src` に `（{duration}秒）`。

**①守り手**：数字（状態）の突き合わせ。
**②テスト**：`_cut_math_note` に実物の文字列でユニットテスト。鳴る側＝「総計21カット（数えた値）／平均約1.5秒〜3秒」+245秒、「12カット・数えた／平均2.5秒」+91秒。鳴らない側（keep）＝「1カットの平均秒数は約2.4秒」、「43カット・数えた／平均8.0秒」+344秒。**`phrasing.py` に置かないこと**（`from phrasing import *` は束縛をコピーするので `bot.CUT_MATH_TOL` の差し替えが届かず、テストは通るのに何も検証しない）。

- 公開日から「再生数÷経過日数」で伸びを語らせる：`TREND_DAILY_DAYS=1825`（5年）・中央値151回の母集団では「新しくて10回」が最上位に来る新種の作り話。**伸びは語らせない**。
- `listing` を `targets`（視聴5本）から作る：n=5 で傾向は出ず、同じ5本の再掲になる。市場の広さを見る唯一の窓も失う。
- 別名で検索も引く／`_QUERY_ALIAS` を検索語に昇格：`_query_variants` の戻り値を完全一致で固定しているテストが2件落ちる。かつ `len(videos) >= max(10, TREND_DEEP_COUNT*3)=15` の break（`TREND_POOL=100`）で**現状デッドコード**。2本/回・limit=100 だと 16レポート×600≒9,600/10,000 で枠に張り付く。表は「タイトルの語彙」であって検索語の候補ではない。
- ジャンルを巡回から自動で外す：研修0%は語の当て方の問題で、`_todays_genres` の「9日で全9ジャンル一巡」保証が崩れる。会社紹介は 09-23 に 0/5 でも 09-25 に 4/5 に戻っている。
- 同日2巡をやめる：`TREND_GENRES_PER_DAY=2 × TREND_MAX_RUNS_PER_DAY=8`＝16枠に対しジャンル9なので、1日のレポートが16→9〜10（分析量4割減）。上書き問題自体は `9f97aa7`（09-30 05:32）で解決済み。
- 2巡目だけ検索語を変える：既に差し替え済み（研修動画→マニュアル動画）。9ジャンルと1対1が崩れる。
- 展示会・サービス紹介の当たり判定を触る：どちらも **off 0本**。直すのは順位付けだけ。
- MV の題材選び（検索順・ショート除外・本編判定）：`82baa67`（09-23 06:55）で終息済み。off は 09-21/22 の2日に集中。
- `_daily_order` の門のしきい値を `>=10` に：60日シミュレーションで上位5本のAPI関連順位は 19.0→20.5・20位以降49%→49% でほぼ不変（門が発動した側は `rng.shuffle` で全シャッフルなので「関連順が残る」は成立しない）。
- ジャンル別の上限尺の列を足す：**そういう表が存在しない**（ジャンルは `gen_settings` の1本の文字列を `_GENRE_SPLIT_RE` で割ったもの）。`_query_core` キーの表＋既定値にするしかない。
- 失敗巡の枠の無駄：`errors.log` の 09-30 の3組は `ClientConnectorDNSError`（リクエストが到達していない）＝**ユニット消費0**。動機が消えている。
- ファイル分割／判定を別ファイルへ切り出す：テストがモジュール変数86個の差し替えと `getsource(_run_trend_study)` の本文検査で守りを効かせているので、移すと守りが黙って消える。

## 5. 一番妥当だと思う打ち手

**まず C0（測る材料を残す1コミット）だけを入れて9日一巡ぶん溜めること**——off 29% が最大の害なのに、尺で何本落ちたか・候補プールに誰がいたか・取りこぼしが何本かが**現在どこにも残っていない**ので、C1以降のどの手当ても効いたかどうかを永久に確認できない。落とすものが1つも無く、既存の守りにも一切触らない唯一の単位でもある。
