# 構成案ひな形

実案件の構成案は、これをコピーして埋める。

**この型は社外に出さない（2026-09-24 の判断）。**
サイトに載せると真似される側に回る。受注0本の今、差別化になるのは
「型を知っていること」そのものなので、**提案書の中でだけ使う**。

だから各節に **【社外OK】／【社内のみ】** を付けてある。
お客様に渡すのは【社外OK】だけ。**根拠になった実測値そのものは渡さない。**
渡すのは、そこから出た「この案件ではこうする」という結論の方。

| | 社外に出す | 社内に留める |
|---|---|---|
| 例 | 「このカットは2秒で切ります」 | 「実測32本の中央値が3.3秒で、ナレ無しは1.5〜2.3秒だから」 |
| 例 | 「ここは実写素材をご用意ください」 | 「AIは実在ロゴの文字を安定して描けないから」 |

数字の引き出しは `成果物/映像の型/` と `成果物/事例素材一覧/`。

---

## 0. 埋める前に決めること【社内のみ】

**順番を守る。**ここを逆にすると、後で必ず合わなくなる。

1. **視聴者と、見た後にしてほしいこと**を1行で決める
2. **ナレーションの有無**を決める → これがカット尺を決める（下の 3 を見る）
3. **ナレーション原稿を先に確定させる**（AIでもまず原稿を書く）
4. 原稿の**一文ごとに1カット**を割り当てる
5. そこで初めてカット表を書く

> 「何秒のカットを何本」から入ると、原稿を載せた時点で必ずどこかが余る／足りない。
> 実測でも、伸びている会社紹介動画の5本中4本は
> **「ナレーション一文の区切り＝カット切り替え＝テロップ表示」が1:1**だった。

## 2. 設計方針【社外OK】

お客様に読ませる部分。**「こうします」と言い切る。**実測値は書かない。

- **カットの長さ**：〔　〕秒前後を基本にします。〔理由を1行。例：ナレーションの
  一文ごとに切り替えるため〕
- **テロップ**：〔画面下部に位置を固定し、最初から最後まで／要点だけ〕。
  1枚あたり〔10〜20〕字に収めます。**音を切っても内容が伝わる**設計です
- **音**：環境音は落とし、〔ナレーション／インタビュー音声〕＋BGMに整理します。
  〔　〕の場面だけ生音を残します
- **冒頭〔3〕秒**：〔何を出すか〕。〔理由を1行〕
- **締め**：〔大テロップ／働く人の姿／検索窓／ロゴ〕

### 尺の使い分けのご提案【社外OK・任意】

> 同じ素材から**〔90〕秒のフル版と〔30〕秒のダイジェスト版**を書き出せます。
> 採用サイトには前者、SNS・展示会には後者、と出し分けられます。
> （2本目は 1本目の1割ほどの追加でつくれます）

## 3. カット尺の決め方【社内のみ】

実測（`成果物/映像の型/会社紹介動画の型.md`）から。

| | 平均カット秒 |
|---|---|
| ナレーション**無し**（テロップも少ない） | **1.5〜2.3秒** |
| ナレーション**無し・テロップで語る** | **2.5〜4.5秒** |
| ナレーション**有り** | **4〜9秒**（文の長さに合わせる） |
| 全体の中央値 | 約3.3秒（2〜4秒の帯に47%） |

**テロップで語る設計なら 1.5〜2.3秒では足りない。**読む時間が要る。
想工業の実績が 59秒 / 19カット ＝ 平均3.1秒（テロップ有り 2.5〜4.5秒、
無し 1.5〜4.0秒）。**「ナレーション無し」を一括りにしない。**
（2026-09-24：`成果物/〇〇工業_会社紹介動画/構成案（ひな形版）.md` を
実際に埋めて見つけた）

MVの型を会社紹介に転用するなら 1.2〜3.6秒。
**CMのリズム（自分の過去の実測で中央値0.90秒）は持ち込まない。** 別物。

## 4. カット表【社外OK（方式の列は社内のみ）】

お客様に出すときは **#／尺／内容／テロップ** の4列だけにする。
**「方式」「AI可否」「備考」はこちらの作業用。**

| # | 尺 | 内容 | テロップ | 方式 | AI可否 | 備考 |
|---|---|---|---|---|---|---|
| 1 | 0–3 | 〔　〕 | 〔　〕 | t2v | ○ | |
| 2 | 3–5 | 〔　〕 | 〔　〕 | i2v(A) | ○ | 顔の一貫性は参照画像で固定 |
| 3 | 5–7 | 〔　〕 | — | **実写** | **×** | 〔理由。ロゴ／図面／画面／実機〕 |

### 方式の書き分け

| 方式 | 使うとき |
|---|---|
| `t2v` | 人物が出ない。背景・設備・空撮・抽象 |
| `i2v(A)` | 同じ人物を繰り返し出す。**キャラクターシートを先に作る** |
| `i2v(静止画→動画)` | 実物の写真をお預かりして動かす。製品の水平パンなど |
| **実写** | 下の「AIで作れないもの」に当たるもの。**お客様に素材をお願いする** |

## 5. AIで作れない＝素材をお願いするもの【社内のみ・判定用】

ここに当たったら、**提案書の「ご用意いただくもの」に書く。**
「できません」ではなく「ご用意ください」として出す。

| 当たるもの | 提案書での言い方 |
|---|---|
| 企業ロゴ・社名・看板の文字 | 「ロゴデータ（ai / svg / 透過png）をお預かりします」 |
| 実在メーカーの機械・実機 | 「〔機種〕の写真を数点お預かりします」 |
| 設計図・仕様図面 | 「図面の画像をお預かりします」 |
| Webサイト・ソフトの画面 | 「画面のキャプチャをお預かりします」 |
| QRコード | 「QRは別途こちらで作成し、映像に合成します」 |
| 社長・社員の証言 | 「**ご本人が話された事実そのものに価値がある**ので、ここは撮影 or 既存素材をお使いください」 |
| 20秒を超えるワンカット | カットを割る設計にする（提案書には書かない） |

**「作れないものがある」ことを先に言う方が、後で揉めない。**
実際、証言部は「本人が実際に話した」という真正性が価値なので、
AIで代替する意味がない——そう説明すると通りやすい。

- 〔ナレーション原稿の元になる内容。こちらで書き起こします〕

## 7. お見積り【社外OK】

**金額は手で打たない。**必ずこれで出す。

```
cd ~/so-portfolio/discord-groupchat
venv/bin/python tools/make_doc.py 見積書 --to 〔社名〕 --title 〔件名〕 \
    --tier 〔梅/竹/松〕 --sec 〔秒〕 --count 〔本数〕 --nar 〔ai/human/none〕
```

段の選び方（実案件の判断基準）

| 段 | 当てはまるとき |
|---|---|
| 梅 | 実写なし／人物は単カットのみ／キャラクターの一貫性が要らない |
| 竹 | テロップと音声の同期作業がある／人物は出るがリップシンクは不要 |
| 松 | 複数人物の顔を通して一貫させる／ポーズ差し替え／実写合成 |

**尺だけで段を決めない。**決めるのは「顔の一貫性が要るか」。

## 8. 出す前の社内チェック【社内のみ】

- [ ] ナレーション原稿を先に確定させたか。カットをその区切りで割ったか
- [ ] カット尺がナレーションの有無と噛み合っているか（3 の表）
- [ ] テロップの位置を固定したか。1枚10〜20字に収まっているか
- [ ] 冒頭3秒で「誰の・何の話か」が出ているか（ロゴだけで終わっていないか）
- [ ] AIに文字（ロゴ・看板・図面・UI・QR）を書かせようとしていないか
- [ ] 「ご用意いただくもの」に、実写が要るカットぶんが全部載っているか
- [ ] 金額を `make_doc.py` で出したか（手で打っていないか）
- [ ] **実測値そのものを提案書に書いていないか**（型は社外に出さない）
- [ ] 他社の事例映像を資料に入れていないか（自社で作ったものだけを見せる）

## 付録：書き上がったあとの流れ

構成案 → 〔見積書〕 → 〔業務委託契約書〕 → 制作 → 納品 → 〔請求書〕

書類は `成果物/書類ひな形/` から。文面は `成果物/_テンプレート/営業文面.md`。

**このひな形を実際に1本埋めた見本**が `成果物/〇〇工業_会社紹介動画/` にある
（**架空のクライアント**。そのまま送らない）。

- `構成案（ひな形版）.md` … 埋めた側。【社外OK／社内のみ】が付いたまま
- `提案書（社外用）.md` … そこから【社外OK】だけを抜いた、送れる形
- `構成案と素材一覧.md` … 制作の実務記録（プロンプト・生成設定・失敗の履歴）

往復のメールの実例も同じフォルダにある（初稿提出〜フィードバック4往復〜納品）。
