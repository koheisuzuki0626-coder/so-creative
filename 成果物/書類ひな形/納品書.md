# 納品書（ひな形）

<img src="../ロゴ/logo-lockup.png" alt="so-creative" width="220">

**納品した事実と、その日付を記録する書面。**

```
cd ~/so-portfolio/discord-groupchat
./venv/bin/python tools/make_doc.py 納品書 --to "株式会社〇〇" \
  --title "会社紹介動画" --sec 60 --count 1 --tier 竹
```

| 指定 | 既定 |
|---|---|
| `--delivered` | 省略すると当日 |
| `--handover` | 「Google ドライブの共有リンクにてお渡ししました（ダウンロード期限はございません）」 |
| `--no` | 省略すると `D-YYYYMMDD-01` |

---

## なぜ要るか

**契約書に検収の定めは無く、支払の起算は「納品日から30日以内」**（業務委託契約書 第5条2項）。
つまり**納品日がいつかが、入金日を決める**。

いま納品日を示しているのは請求書の摘要欄だけ。それで通る相手もいるが、
**経理が納品書を別に求めてくる会社はよくある**。言われてから作ると1往復遅れ、
そのぶん入金が遅れる。先に用意しておく。

## 金額は書かない

納品書に金額は載せていない。**金額は請求書の役目**で、2通に別々の数字が載ると
食い違いの元になる（実際、見積書と契約書で金額がずれる事故が 2026-09-24 に起きている）。

## 検収書は作らない

契約書に検収の定めが無いため。納品書の末尾にもその旨を書いてある。
**相手から検収書を求められたら、それは契約書に無い手続き**なので、
受けるかどうかをその場で決める（受けるなら、検収の期限と
「期限内に異議が無ければ検収したものとみなす」を必ず入れる）。

## 書いてあること

| | 中身 |
|---|---|
| 納品日 | 支払の起算日。ここが一番大事 |
| 品目・仕様 | MP4（1920×1080 / 30fps / H.264 / AAC）／尺・本数 |
| お渡し方法 | 既定は Google ドライブの共有リンク |
| ご確認のお願い | 修正は第4条の範囲（段ごとの回数）／著作権は第6条／**意図しない類似の確認のお願い（第6条6項）** |
| お支払い | 別途請求書を送る旨と、納品日から30日以内 |

**「意図しない類似を公開前に確認してください」は、ここにも必ず残すこと。**
契約書 第6条6項で合意している内容だが、納品の瞬間にもう一度伝えるのが実質的な防御になる。
